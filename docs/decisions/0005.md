# 0005: Lock the Escape Pod with one flag checked before the move

- **Status:** Accepted
- **Date:** 2026-11-21
- **Round:** 5
- **Related requirements:** R10 (Keycard and Locked Escape Pod), R3
  (revised escape condition); AC-R10.x and AC-R3.9-3.12 in `spec.md`
  Section 6

## Decision (Y-statement)

In the context of **making the Escape Pod door start locked, letting the
player unlock it with `use keycard` at the Airlock Junction, and revising
R3 so that reaching the pod without unlocking it is no longer a win, while
keeping rules in `game.py` and text in `cli.py` (ADR 0001), read-only world
data (ADR 0002), live item state on `Game` (ADR 0003), and the single,
tested turn order in `Game._move()` (ADR 0004)**,

facing **the need for a refused move to cost no oxygen or health and leave
the map unchanged, for the lock to outlive the keycard (the user chose
"stays unlocked even if the keycard is dropped"), for the keycard to stay
in play so item counting is not affected, for the win check from Rounds
1-4 to keep working unchanged, and for the Round 1 rule against
building for features nobody asked for yet**,

we decided for **a single `pod_locked: bool` on `Game` (`True` in a new
game), checked in `Game._move()` straight after the "no exit" check and
**before** the room changes, returning a new `LOCKED` outcome; the
reader's location as `KEYCARD_READER = "airlock_junction"` in `world.py`
(it is part of the ship layout), with `KEYCARD = "keycard"` as a rule
constant in `game.py`; a `_use_keycard()` branch in `Game._use` after the
existing "carried?" check that answers `WRONG_PLACE` away from the reader,
`ALREADY_UNLOCKED` if the door is open, and otherwise clears `pod_locked`
and returns `UNLOCKED`; and no change to the win check itself, because a
move into a locked pod never gets that far**,

and neglected **turning exits into `Exit` objects with lock conditions (the
Round 1 spec's suggestion; too much for one door, and it would change
every exit in `world.py`); a general set of locked rooms or a lock/key
table (no second lock is asked for); treating "carrying the keycard" as
the key, with no `use` step (R10 asks for `use keycard`, and dropping the
card would lock the door again); adding an "unlocked" condition to the
win check while letting the player into a locked pod (the player would
pay oxygen and possibly take damage for a move that doesn't count);
making the keycard a consumable like the medkit; and marking the door as
locked on the `Exits:` line or the map (the user chose to keep the Round 1
display unchanged)**,

to achieve **a lock that is checked in the one function that moves the
player, so a refused move can't cost oxygen or health or add the pod to
`visited`; a revised R3 that needs no extra win condition, because
"reached the pod" now implies "unlocked it"; the same `use <item>`
command and parser rule from Round 4, with the "carried?" check still
first; item counting unchanged (the keycard is never used up); and output
the CLI renders from the outcome alone, as in ADRs 0001-0004**,

accepting **that the lock is hard-wired to the Escape Pod and a second
locked door would need a small refactor (for example, a set of locked
room ids); that the shortest win grows from 6 to 8 moves (4 oxygen left
instead of 6), which changed the expected results of the Round 1-4 tests
that walked straight into the pod and needed "(Round 5)" notes on
AC-R3.4, AC-R3.8, AC-R6.6, AC-R8.8 and AC-R9.7; and that a future
save/load must also save `pod_locked`**.

## Consequences

- `Game.handle` needs no new handler or parser rule. `_move()` gains one
  check, `_use()` gains one branch, and `Outcome` gains `LOCKED`,
  `UNLOCKED`, `ALREADY_UNLOCKED`, and `WRONG_PLACE`. `TurnResult` is
  unchanged.
- The turn order in `_move()` is now: exit exists? → **pod locked?
  (`LOCKED`, nothing changes)** → move → visited → oxygen −1 → hazard
  damage → health 0? (`DIED`) → pod with oxygen > 0? (`WON`) → oxygen 0?
  (`LOST`).
- `cli.render_result` answers `LOCKED` like `BLOCKED`: a two-line lock
  message (with a keycard-reader hint) followed by the room's exits.
- With 12 oxygen and 10 health, both 8-move keycard routes win with 4
  oxygen and 8 health, every winning route takes 8 or 10 moves, and the
  game is still winnable without healing (checked by tests and by an
  exhaustive search). Round 4's finding that health can only reach 0 on
  move 12 still holds, since the lock only refuses moves.
- A future save/load feature must save `pod_locked` alongside `room_id`,
  `oxygen`, `health`, `status`, `visited`, `room_items`, and `inventory`.
